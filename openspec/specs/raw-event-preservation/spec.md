# Сохранение исходных событий

## Purpose

Определяет неизменяемый журнал наблюдений, необходимый для происхождения данных, расследования ошибок и повторной нормализации.

## Requirements

### Requirement: Сохранение исходного объекта

Система SHALL сохранять каждый поддерживаемый к приёму объект Telegram максимально близко к полученному представлению до формирования производного состояния.

#### Scenario: Получено известное событие

- **GIVEN** collector получил событие известного типа
- **WHEN** событие передано в обработку
- **THEN** журнал содержит полный исходный объект события
- **AND** содержит тип события и время его получения системой
- **AND** содержит идентификаторы чата и сообщения, когда они доступны в событии

#### Scenario: Получено неизвестное событие

- **GIVEN** collector получил событие, для которого нет нормализатора
- **WHEN** событие обработано
- **THEN** исходный объект всё равно сохраняется в журнале
- **AND** отсутствие нормализатора не приводит к потере наблюдения

### Requirement: Append-oriented история наблюдений

Система SHALL добавлять новые отличающиеся наблюдения, не заменяя ими ранее сохранённые события.

#### Scenario: Последовательные изменения одного сообщения

- **GIVEN** ранее сохранено событие для сообщения
- **WHEN** приходит отличающееся событие для того же сообщения
- **THEN** новое событие получает отдельную запись журнала
- **AND** прежняя запись остаётся неизменной

### Requirement: Дедупликация точной повторной доставки

Система SHALL распознавать точный повтор исходного объекта по устойчивому отпечатку канонического содержимого.

#### Scenario: Одинаковое событие доставлено повторно

- **GIVEN** исходный объект уже сохранён
- **WHEN** collector повторно получает объект с тем же каноническим содержимым
- **THEN** в журнале остаётся одна запись этого объекта
- **AND** повтор не запускает повторное изменение нормализованного состояния

#### Scenario: Содержимое события отличается

- **GIVEN** в журнале уже есть событие для тех же идентификаторов
- **WHEN** приходит объект с отличающимся содержимым
- **THEN** он сохраняется как новое наблюдение

### Requirement: Происхождение нормализованных версий

Система SHALL связывать каждую созданную версию сообщения с конкретным исходным событием.

#### Scenario: Создана новая версия сообщения

- **GIVEN** исходное событие привело к отличающемуся состоянию сообщения
- **WHEN** система создаёт историческую версию
- **THEN** версия содержит ссылку на запись исходного события
- **AND** по ссылке доступен полный первоначально полученный объект

### Requirement: Сохранение события при ошибке нормализации

Система SHALL сохранять исходное наблюдение, даже если его производная обработка завершилась ошибкой.

#### Scenario: Нормализатор не понимает новую форму события

- **GIVEN** корректный исходный объект содержит неподдерживаемую форму данных
- **WHEN** нормализация вызывает ошибку
- **THEN** исходное событие остаётся зафиксированным
- **AND** ошибка содержит идентификатор и тип проблемного события
- **AND** collector продолжает принимать следующие события
