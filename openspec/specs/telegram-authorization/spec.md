# Авторизация Telegram

## Purpose

Определяет поведение первичной и повторной авторизации collector в Telegram без сохранения секретов в репозитории.

## Requirements

### Requirement: Конфигурация учётных данных

Система SHALL получать идентификатор приложения, секрет приложения, номер телефона и ключ локальной базы из внешней конфигурации среды выполнения.

#### Scenario: Запуск с настроенными значениями

- **GIVEN** обязательные параметры Telegram заданы во внешней конфигурации
- **WHEN** collector запускается
- **THEN** параметры передаются подсистеме Telegram для начала авторизации
- **AND** реальные значения не требуется хранить в репозитории

#### Scenario: Отсутствует обязательное значение

- **GIVEN** обязательный параметр Telegram отсутствует или пуст
- **WHEN** collector загружает конфигурацию
- **THEN** запуск завершается с понятной ошибкой конфигурации
- **AND** collector не имитирует успешное подключение

### Requirement: Интерактивная первичная авторизация

Система SHALL поддерживать интерактивные шаги авторизации, запрашиваемые Telegram для конкретной учётной записи.

#### Scenario: Требуется код подтверждения

- **GIVEN** Telegram запросил код подтверждения
- **WHEN** оператор вводит полученный код
- **THEN** система передаёт код Telegram и продолжает авторизацию

#### Scenario: Требуется пароль дополнительной защиты

- **GIVEN** для учётной записи включена дополнительная защита паролем
- **WHEN** Telegram запрашивает пароль
- **THEN** система принимает пароль интерактивно без его записи в проектные файлы

#### Scenario: Требуется подтверждение электронной почты или регистрация

- **GIVEN** Telegram запросил адрес, код электронной почты либо регистрационные данные
- **WHEN** оператор вводит требуемые значения
- **THEN** система передаёт соответствующий ответ и продолжает штатный процесс авторизации

### Requirement: Подтверждение с другого устройства

Система SHALL сообщать оператору о необходимости подтверждения на другом устройстве, если Telegram выбрал такой способ авторизации.

#### Scenario: Получена ссылка подтверждения

- **GIVEN** Telegram ожидает подтверждение с другого устройства
- **WHEN** collector получает состояние с подтверждающей ссылкой
- **THEN** collector записывает понятное уведомление и ссылку в журнал выполнения
- **AND** не считает авторизацию завершённой до подтверждения

### Requirement: Сохранение состояния сессии

Система SHALL хранить локальное состояние Telegram отдельно от образа приложения так, чтобы успешная сессия переживала штатные перезапуски.

#### Scenario: Повторный запуск после авторизации

- **GIVEN** оператор ранее успешно авторизовал collector
- **AND** постоянное состояние Telegram сохранено
- **WHEN** collector перезапускается с тем же ключом локальной базы
- **THEN** система использует сохранённую сессию
- **AND** не требует повторного кода без требования со стороны Telegram

### Requirement: Переход в готовое состояние

Система SHALL начинать загрузку доступных основных и архивных чатов только после получения состояния успешной авторизации.

#### Scenario: Авторизация завершена

- **GIVEN** Telegram сообщил о готовности авторизованной сессии
- **WHEN** collector обрабатывает это состояние
- **THEN** collector отмечает соединение готовым
- **AND** запрашивает загрузку основных и архивных чатов
