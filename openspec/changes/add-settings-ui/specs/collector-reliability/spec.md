## ADDED Requirements

### Requirement: Запуск collector только с полной конфигурацией

Система SHALL отделять доступность административной страницы от готовности collector и SHALL запускать сбор только по явной команде оператора с полной проверенной конфигурацией.

#### Scenario: Первоначальная конфигурация не завершена

- **GIVEN** административная панель запущена
- **AND** обязательные настройки collector отсутствуют
- **WHEN** процесс проверяет готовность
- **THEN** панель остаётся доступной для настройки
- **AND** collector не подключается к Telegram или PostgreSQL

#### Scenario: Полная конфигурация сохранена, но не проверена

- **GIVEN** оператор сохранил полную валидную draft-ревизию
- **WHEN** обязательные проверки или явная команда запуска отсутствуют
- **THEN** collector остаётся остановленным

#### Scenario: Проверенная конфигурация запущена

- **GIVEN** текущий draft прошёл обязательные проверки
- **WHEN** оператор явно запускает сбор
- **THEN** collector запускается с согласованным снимком active revision

### Requirement: Контролируемый перезапуск collector

Система SHALL завершать текущий экземпляр collector и освобождать его ресурсы до запуска экземпляра с новой ревизией.

#### Scenario: Изменены параметры подключения

- **GIVEN** collector работает с предыдущей ревизией
- **WHEN** активируется изменение Telegram или database credentials
- **THEN** старый цикл получает запрос штатной остановки
- **AND** его Telegram-клиент и database connections закрываются
- **AND** только после этого запускается новый экземпляр

#### Scenario: Новая ревизия не запускается

- **GIVEN** предыдущая ревизия работала
- **WHEN** запуск новой ревизии завершается ошибкой
- **THEN** панель показывает состояние ошибки и номера сохранённой и применённой ревизий
- **AND** не объявляет новую конфигурацию успешно применённой
- **AND** сохранённые raw events, сообщения и версии не изменяются из-за неуспешного запуска

#### Scenario: Оператор останавливает collector

- **GIVEN** collector находится в starting или running
- **WHEN** supervisor получает допустимую команду stop
- **THEN** текущий экземпляр штатно освобождает TDLib и database resources
- **AND** desired state становится stopped без удаления persistent state

### Requirement: Диагностическое состояние жизненного цикла

Система SHALL публиковать безопасное состояние supervisor и время последнего успешно обработанного update отдельно от состояния web-панели.

#### Scenario: Сбор работает

- **GIVEN** collector успешно запущен
- **WHEN** update сохранён
- **THEN** status содержит состояние running, applied revision и время последнего успешного update

#### Scenario: Сбор завершился с ошибкой

- **GIVEN** collector не смог запуститься либо неожиданно завершился
- **WHEN** status обновляется
- **THEN** он содержит состояние error, безопасную категорию ошибки и applied revision
- **AND** не содержит credentials или Telegram challenge values

### Requirement: Совместимость существующего запуска

Система SHALL сохранять возможность запуска collector только из валидной внешней конфигурации без использования административной страницы.

#### Scenario: Панель отключена оператором

- **GIVEN** все обязательные параметры доступны в среде выполнения
- **AND** административный listener явно отключён
- **WHEN** сервис запускается
- **THEN** collector работает по существующему сценарию
- **AND** сетевой административный порт отсутствует
