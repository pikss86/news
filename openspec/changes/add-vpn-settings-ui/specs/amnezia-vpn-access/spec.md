## Purpose

Ограничивает сетевую доступность административной страницы интерфейсом и адресным пространством приватной Amnezia VPN, сохраняя закрытое состояние при ошибочной конфигурации.

## ADDED Requirements

### Requirement: Безопасное определение Amnezia-сети

Система SHALL автоматически определять адрес Amnezia-интерфейса и связанную приватную подсеть при однозначном результате и SHALL поддерживать явный bootstrap override для нестандартной установки.

#### Scenario: Найден один подходящий интерфейс

- **GIVEN** host содержит ровно один поддерживаемый активный Amnezia-интерфейс с непубличным адресом
- **WHEN** административный сервис запускается
- **THEN** он выбирает адрес интерфейса и его VPN CIDR
- **AND** публикует listener только на выбранном адресе

#### Scenario: Задан явный безопасный override

- **GIVEN** оператор задал адрес существующего Amnezia-интерфейса и корректный private CIDR
- **WHEN** административный сервис запускается
- **THEN** проверенный override используется вместо autodetection

#### Scenario: Интерфейс не найден или результат неоднозначен

- **GIVEN** не найден ни один подходящий интерфейс либо найдено несколько кандидатов
- **AND** безопасный override отсутствует
- **WHEN** административный сервис запускается
- **THEN** панель остаётся недоступной
- **AND** журнал перечисляет только безопасную диагностическую информацию и способ задать override
- **AND** listener не переходит на другой интерфейс

#### Scenario: Override содержит wildcard или публичную подсеть

- **GIVEN** bind-адрес разрешает все интерфейсы либо CIDR не является допустимой приватной сетью
- **WHEN** override проверяется
- **THEN** запуск панели отклоняется

### Requirement: Двойное ограничение доступа

Система SHALL одновременно ограничивать интерфейс публикации и проверять непосредственный адрес каждого клиента по разрешённым CIDR.

#### Scenario: Клиент находится в разрешённой Amnezia-подсети

- **GIVEN** запрос поступил на VPN-интерфейс
- **AND** непосредственный адрес клиента входит в разрешённый CIDR
- **WHEN** клиент запрашивает административную страницу
- **THEN** запрос допускается к последующей административной аутентификации

#### Scenario: Клиент находится вне VPN-подсети

- **GIVEN** адрес клиента не входит ни в одну разрешённую подсеть
- **WHEN** клиент запрашивает любой путь панели
- **THEN** запрос отклоняется до чтения или изменения настроек

### Requirement: Недоверие к подменяемым заголовкам адреса

Система SHALL использовать адрес сетевого соединения и SHALL NOT доверять заголовкам перенаправления клиента без явно настроенного доверенного proxy.

#### Scenario: Внешний клиент подставил X-Forwarded-For

- **GIVEN** непосредственный адрес клиента запрещён
- **AND** запрос содержит заголовок с разрешённым VPN-адресом
- **WHEN** выполняется проверка CIDR
- **THEN** запрос отклоняется

### Requirement: Изменение VPN selection требует безопасного перезапуска

Система SHALL применять изменение bind-адреса и разрешённых CIDR только после перезапуска административного listener.

#### Scenario: VPN-адрес изменился

- **GIVEN** оператор изменил bootstrap override либо состав сетевых интерфейсов
- **WHEN** административный сервис ещё не перезапущен
- **THEN** продолжает действовать предыдущая сетeвая политика
- **AND** после перезапуска новая политика проверяется до открытия listener

### Requirement: Отсутствие публичного fallback

Система SHALL NOT автоматически открывать административную страницу на публичном интерфейсе при исчезновении Amnezia-интерфейса.

#### Scenario: VPN-интерфейс недоступен

- **GIVEN** настроенный Amnezia-адрес отсутствует на host
- **WHEN** listener запускается или перезапускается
- **THEN** bind завершается ошибкой
- **AND** административный порт не публикуется на другом интерфейсе
